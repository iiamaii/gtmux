앱 업데이트

데스크톱 관리 화면의 Updates에서 Check for updates로 새 안정 버전을 확인하고 Download update로 다운로드·검증합니다. Automatic checks and downloads는 기본적으로 꺼져 있습니다. 켜면 앱 시작과 이후 6시간마다 확인합니다. 설치는 항상 Install and restart로 직접 확인해야 하며, 서버 비밀번호를 설정했다면 입력해야 합니다. 실행 중인 터미널 프로그램은 종료되고 저장된 레이아웃은 유지됩니다. 종료 인증이 거부되면 설치하지 않고 다운로드된 상태를 유지합니다.

패키지 앱은 electron-updater로 릴리스 메타데이터의 SHA512를 검증합니다. 해시 검증은 신뢰할 수 있는 배포 서버나 플랫폼 코드 서명을 대체하지 않습니다. 일반적인 앱 종료 때 자동 설치하거나 이전 버전으로 다운그레이드하지 않습니다.

릴리스 준비

GTMUX_RELEASE_REPOSITORY=owner/repo를 지정해 빌드하면 GitHub 업데이트 피드를 포함합니다. 아티팩트 워크플로는 현재 저장소와 vMAJOR.MINOR.PATCH 태그의 버전을 사용하며 설치 파일, 업데이트 YAML, blockmap을 만듭니다. 워크플로 아티팩트만 업로드하고 GitHub 릴리스 게시·배포는 하지 않습니다. 관리자가 패키지 검토·서명 후 해당 파일과 메타데이터를 릴리스 피드에 게시해야 합니다. 여러 아키텍처의 산출물을 합칠 때 latest YAML을 덮어쓰지 말고 각 파일 항목을 유지해야 합니다.

릴리스 메타데이터 환경변수는 패키징 단계에만 전달합니다. GTMUX_RELEASE_TAG는 버전 기록 스크립트에만, GTMUX_RELEASE_REPOSITORY는 electron-builder에만 전달합니다. 작업 전체나 서버·테스트 실행 환경에 이 변수를 설정하지 마세요. 서버는 GTMUX_ 환경변수를 설정으로 엄격하게 해석하므로 알 수 없는 필드를 거부합니다.

업데이트 대상은 Windows NSIS, macOS 앱, Linux AppImage입니다. macOS 배포에는 정상적인 설치·업데이트를 위한 서명과 공증이 필요합니다. 압축을 푼 개발 빌드, 웹 전용 관리자, Linux 압축 파일, 피드 없는 로컬 패키지는 자동 업데이트를 사용할 수 없는 이유를 표시합니다. 압축 파일로 설치했다면 서버를 종료하고 실행 파일과 프런트엔드를 함께 교체하세요. 설정과 Store는 삭제하지 않습니다.

loopback 피드 테스트에서 실제 updater SDK의 메타데이터 조회·다운로드·SHA512 변조 거부를 검증합니다. 이 SDK 검증은 업데이트를 설치하지 않습니다. 별도의 Windows 실제 설치 검증은 아래 절차를 사용하며 공개 릴리스를 게시하지 않습니다. macOS/ARM 실행 결과와 서명된 릴리스의 전체 업데이트 경로는 배포 전 확인 항목입니다.

Windows 앱 설치와 시작 메뉴 등록에는 GitHub Release가 필요하지 않습니다. 자동 업데이트에는 설정된 피드와 실제 발행된 새 버전이 필요합니다. 첫 릴리스 전에 피드가 연결된 미리보기 앱을 설치할 수 있지만, 릴리스가 생기기 전에는 업데이트 확인이 실패할 수 있습니다. 안정 버전 업데이트는 같은 앱 ID를 유지하고 더 높은 버전의 설치 파일·latest.yml·blockmap을 같은 신뢰할 수 있는 저장소에 발행해야 합니다. git push만으로 업데이트가 배포되지는 않습니다.

Windows 실제 설치·업데이트 검증

별도 앱 ID의 테스트 앱으로 0.1.0 설치 → 0.1.1 조회·다운로드·검증 → 서버 정상 종료 → NSIS 설치 → 0.1.1 자동 재실행을 로컬에서 검증했습니다. TOML과 Store 확인 파일도 유지됐습니다. 공개 릴리스는 사용하지 않았으며, GitHub 배포나 서명된 릴리스 검증과는 구분합니다.

Windows Node와 대화형 Windows 데스크톱에서 실행합니다. 네이티브 Windows 서버·런타임 DLL·프런트엔드를 launcher의 resources에 준비하거나 GTMUX_TEST_SERVER_RESOURCES로 해당 폴더를 지정한 뒤 codebase/launcher에서 실행합니다.

node test/build-windows-update-fixtures.mjs
node test/windows-update-install-smoke.mjs

서명하지 않은 별도 테스트 앱 gtmux Update Test를 설치하고, 루프백 포트 39241에서 업데이트를 제공하며 해당 설치 마법사만 조작합니다. 새 실행 파일 버전과 설정 보존을 확인한 뒤 테스트 앱을 제거합니다. 테스트 프로필이나 캐시가 이미 있으면 덮어쓰지 않고 중단합니다.
