# 서버 관리

## 첫 실행

관리자는 임의의 loopback 포트에서 동작하고 CLI 모드에서는 전용 최초 접속 URL을 출력합니다. 이 제어 주소는 터미널 서버와 별개이며 공개 프록시로 전달하지 않습니다. 별도 세션 쿠키와 같은 출처의 JSON 요청이 필요합니다.

절대 경로의 작업 폴더, 1024–65535 포트, 접근 방식과 백그라운드 실행 여부를 선택합니다. 포트가 사용 중이면 기존 프로세스를 종료하지 않고 실패를 표시합니다. 설정을 저장하고 서버를 시작한 뒤 작업 화면을 엽니다.

## 설정

첫 설정에서 관리자 전용 TOML을 생성합니다. 설정 후에도 서버를 중지하면 여기서 작업 폴더를 다시 입력·선택하고 **Save setup**으로 저장할 수 있습니다. 외부에서 TOML을 수정했다면 **Reload**로 경로를 다시 읽습니다. 기존 세션과 Store 위치, 별도로 지정한 기본 세션 폴더는 유지됩니다. 다른 서버 설정은 작업 화면의 Settings → Server에서 바꿉니다. 일반 폼과 고급 편집기는 화면을 이동해도 초안을 유지합니다. 저장에는 현재 토큰/비밀번호가 필요하며 외부 수정과 쓰기 실패를 감지합니다. Behavior는 저장 성공 후 즉시 반영하고 나머지 시작 설정은 재시작 후 적용합니다. Appearance는 브라우저별 설정입니다.

관리자는 시작할 때 저장된 TOML을 다시 읽습니다. 접근 방식이나 백그라운드 설정만 바꿔서 기존 서버 설정을 덮어쓰지는 않습니다.

## 종료와 재시작

이 관리형 서버의 모든 터미널 프로그램이 끝난다는 확인 후 종료·재시작합니다. 저장된 레이아웃은 유지합니다. 비밀번호를 설정했다면 현재 서버 비밀번호를 입력합니다. 인증이 거부됐다고 강제 종료하지 않습니다.

서버는 HTTP·WebSocket 연결을 정리하고 새 터미널 생성을 차단한 뒤 자식 프로세스와 attach guard를 정리합니다. 관리 대상은 앱이 직접 실행한 자식 프로세스뿐입니다. 프로세스 이름으로 일괄 종료하거나 WSL 전체를 종료하지 않습니다.

## 문제 해결

관리 화면에 설정·로그 경로가 표시됩니다. 서버 로그의 접속 토큰은 가립니다. 시작 실패 시 오류를 확인하고 다시 시도합니다. 종료 시간 초과는 표시하며 조용히 강제 종료하지 않습니다. attach 소유권은 lock inode를 유지하며 서버 소유의 끊어진 연결만 정리합니다. 접속을 강제하기 위해 실행 중인 `.lock` 파일을 삭제하지 않습니다.

## 숨긴 Activity 표시 복원

워크스페이스의 Settings → Appearance → Terminal activity에서 Activity list를 켜면 사이드바 탭이 복원됩니다. Unread in browser tab은 기본 off이며, Unread output 및 Browser tab indicators와 함께 켜면 제목에 unread 개수가 나타납니다. 표시를 꺼도 포맷과 저장된 사이드바 폭은 유지됩니다.

## 포트 복구와 화면 설정

서버가 중지되었을 때 **Change startup port or recover from a conflict**를 펼치고 저장된 포트를 다시 읽은 뒤 빈 포트로 저장할 수 있습니다. 파일 변경 충돌을 검사하고 나머지 TOML을 보존하며 지원하지 않는 표현식은 덮어쓰지 않습니다. 외부 편집 후에는 파일을 명시적으로 다시 읽고 시작 설정 적용을 위해 재시작하세요. 여러 줄의 loopback 허용 목록은 TOML에서 포트와 함께 수정해야 합니다.

관리 화면도 워크스페이스 디자인 토큰을 공유하며 System·Light·Dark 테마를 제공합니다. Save setup으로 테마를 저장합니다. 워크스페이스의 사이드바 크기 조절 핸들은 방향키(10px), Shift+방향키(50px), Home·End를 지원합니다. Activity 표시 여부별 폭은 별도로 저장되어 새로고침과 on/off 이후에도 유지됩니다.

데스크톱 첫 설정의 **Workspace folder**는 경로를 직접 입력하거나 **Browse…**로 OS 폴더 선택창에서 고를 수 있습니다. 취소하면 입력한 경로가 유지됩니다. 폴더 선택은 입력칸만 바꾸며 **Save setup**을 눌러야 적용됩니다. 웹 전용 관리 화면에서는 서버 경로를 직접 입력합니다. 브라우저의 파일 업로드용 폴더 선택으로는 서버의 절대 경로를 얻을 수 없기 때문입니다.

초기 설정 버튼은 호버 시 은은하게 배경이 바뀌며, 주요 작업과 선택한 메뉴는 강조색을 유지합니다. 동작 줄이기 설정에서는 버튼 전환 효과를 사용하지 않습니다.

**Save setup** 옆의 **Unsaved changes**, **Saving settings…**, **✓ Saved**로 수정·저장 중·저장 완료 상태를 구분할 수 있습니다. 저장 실패 시 **Not saved**와 사유를 표시하며 다시 시도할 수 있도록 입력을 유지합니다.

**Open workspace**는 필요하면 설정된 서버를 먼저 시작하고 준비된 뒤 선택한 앱·브라우저 화면을 엽니다. 서버를 중지한 뒤에도 이 버튼으로 다시 열 수 있습니다. **Start server**는 서버만 실행합니다. 트레이의 Open workspace도 같은 방식으로 동작하며, 서버 제어 버튼 아래에 진행 상태와 열기 실패 사유를 표시합니다.

데스크톱 앱의 **New app window**는 별도 작업 창을 엽니다. 브라우저 탭처럼 창마다 다른 세션에 연결할 수 있습니다. 트레이 메뉴나 Windows/Linux **Ctrl+N**, macOS **⌘N**으로도 열 수 있습니다. 작업 창 하나를 닫아도 다른 창과 서버는 유지됩니다. **Open workspace**는 기존 창을 새로고침하지 않고 앞으로 가져오며, 서버를 재시작했다면 다시 인증합니다. 작업 창이 남아 있으면 서버 관리 창의 닫기는 관리 창만 숨깁니다.
